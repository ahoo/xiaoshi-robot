# 系统架构、功能怎么接在一起、怎么在仿真里亲手验证

这份文档回答三件事：**系统由哪几层组成、一句话的命令是怎么变成动作的、想验证某个功能该怎么亲手点一遍**。所有名字和数字都是从代码里读出来的（每个模块自己的说明、`modes.py` 的抢占表、`people.Guard.CFG`），不是凭印象。

## 1. 分层

```
 你说一句话 / 点一个按钮 / 键盘遥控
        │
 ┌──────▼───────────────────────────────────────────────────────────────────────────────────────────────┐
 │ 说话  voice.py   唤醒词 → 识别（仿真里是模拟）→ 理解 → 谁能让它做什么（权限）→ 要不要先问回去 → 去做     │
 │       lang.py（英文/夹杂）· llm.py（可选，只发文字，动作仍过权限）· wakeword.py（真关键词模型）         │
 │ 声音  soundfront.py acoustics.py doa.py speaker.py assoc.py   声源方向、声纹、“这句话是谁说的”          │
 └──────┬───────────────────────────────────────────────────────────────────────────────────────────────┘
        │ 请求一个模式（start_task / scan_home / charge_now / go_to / idle / teleop）
 ┌──────▼───────────────────────────────────────────────────────────────────────────────────────────────┐
 │ 调度  modes.py  Supervisor   TASK NAV SCAN FETCH TELEOP CHARGE RIGHT IDLE FAULT；谁能打断谁；每 20 ms 一拍│
 │       power.py（电池）· righting.py（摔倒起身）· dock.py（回充电座）· IMU 摔倒检测                      │
 ├──────────────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 安全层  people.py  Guard   夹在“模式”和“轮子、手臂”之间：人靠近就放慢、停住、暂停手臂，不对人身边的东西下手 │
 └──────┬───────────────────────────────────────────────────────────────────────────────────────────────┘
        │ 速度、关节目标
 ┌──────▼───────────────────────────────────────────────────────────────────────────────────────────────┐
 │ 任务  controller.py  Agent   建图 · A* 规划 · 全向路径跟随 · 找东西 · 下手位置 · 抓取/搬运/放置 · 记忆    │
 │ 技能  skills.py（抓、扒出来、放）· arm.py（SO-101 逆运动学）                                           │
 │ 感知  perception.py（前置深度相机找东西、腕部相机看夹没夹住）· localization.py（雷达扫描匹配定位）     │
 │       mapping3d.py + home.py + inventory.py（三维地图、物件记录）· people.py + rgbdet.py（找人、分大人小孩）│
 └──────┬───────────────────────────────────────────────────────────────────────────────────────────────┘
        │ 传感器读数：雷达、里程计、IMU、深度图、关节反馈          ▲ 轮速、关节目标、夹力
 ┌──────▼─────────────────────────────────────────────────────────┴─────────────────────────────────────┐
 │ 驱动层  robot.py   “真机的驱动层会给你的东西”：底盘速度、关节目标、雷达、里程计、IMU、相机             │
 │         ——**现在只有仿真这一层；真舵机的驱动还没写，上面所有层不用改**                                   │
 ├──────────────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 世界  model.py（LeKiwi 三全向轮底盘 + SO-101 + 雷达 + 前臂相机 + 挡条 + 家具、收纳筐、充电座）          │
 │       objects.py（地上的东西：硬的、软的）· people.py 的模拟人 · lidar_models.py · perturb.py（故意加误差）│
 └──────────────────────────────────────────────────────────────────────────────────────────────────────┘
   验收：accept.py（30 项，每项一个场景、一条数字标准）+ test_*.py 台架          实时观察：live.py（本文第 4 节）
```

**接口的方向是单向的**：上层只通过“请求一个模式”“给速度、给关节目标”往下说话，往上拿的只有传感器读数。控制代码不读仿真真值（真值只给评分用，见 `controller.py` 开头的说明）。这就是为什么“驱动层换成真机，上面不用改”这句话是成立的，也是为什么仿真里测出来的东西对真机有意义。

## 2. 一句“收拾一下玩具”是怎么变成动作的

1. **说**：`voice.VoiceSystem.hear('小拾小拾，收拾一下玩具', role='owner')`：认出唤醒词，理解成“收拾”这个意图，查权限表（谁能让它做什么），主人可以，直接执行；回一句“好的，我去收地上的玩具”。
2. **调度**：执行就是 `Supervisor.start_task()`，监督层把模式从 IDLE 换成 TASK（机器人停在充电座上就先“离开充电座”）。
3. **任务**：`Agent.run()` 接手：开机原地环顾建图 → 巡视找东西 → 前置深度相机发现物体（日志：“发现物体#1（约 8×3 cm，高 4 cm），距离 0.87 m”）→ 算下手的位置和朝向 → A* 规划过去 → 走近再近看一次 → `skills.grasp` 夹住（夹力分档加上去，物体一松动就停）→ 搬到收纳筐边 → `skills.place` 放进去（日志：“物体#4 已放进收纳筐”）→ 下一件 → 都放完：“没有待办，回起点”，“任务结束”。
4. **同时一直在跑**：定位（雷达对着自己建的地图）、IMU 摔倒检测、电池记账、**安全层**（看着有没有人）。
5. **打断**：任何时候有更高优先级的事，监督层按下表处理。

**谁能打断谁**（`modes.py`）：

| 事件 | 怎么处理 |
|---|---|
| 摔倒 | 硬切换，压过一切（自己起来） |
| 电池空了 | FAULT，需要人 |
| 电池危急（< 10%） | 硬切到 CHARGE，连人在遥控也压过 |
| 操作员请求（遥控、导航、任务、充电、待命） | 硬切换；正在从摔倒里起身时不行 |
| 电池偏低（电量计读数 < 20%） | 软：TASK 把手里的东西放好、停在两件事之间，再去 CHARGE，充好接着干 |
| 任务做完 | 电池不满就去 CHARGE，然后 IDLE |

## 3. 人和安全层（孩子冲过来时发生了什么）

前臂相机（行进姿势下朝前向上看）→ 深度图里把“竖起来的东西”分块 → 跟踪（一个人一条轨迹）→ 按身高和肩宽分“大人 / 小孩 / 拿不准”（**拿不准一律按小孩办**）→ **Guard** 按下面的距离限制轮子和手臂（`people.Guard.CFG`）：

| | 大人 | 小孩（含“拿不准”） |
|---|---|---|
| 开始放慢（人的表面离机器人） | 1.0 m | 1.4 m |
| 不许朝他开过去、必要时整个任务暂停 | 0.35 m | 0.55 m |
| 手臂在干活而人在手臂够得到的范围里：手臂停住、任务暂停 | 0.40 m | 0.55 m |
| 不对他身边的东西下手（“区域”） | 0.9 m | 1.1 m |

另外有一路**激光雷达上“新出现的东西”**，管相机看不到的方向（相机只朝一个方向看）。手臂伸下去干活时相机看地板（整套任务里约 12% 的时间），那段时间只有雷达这一路。

## 4. 怎么亲手验证：实时观察台 `sim/live.py`

在**你自己的电脑上**跑（这个会话在云端，你的浏览器连不到它；我在这里的容器里用无头浏览器把整个界面点过一遍，录像在对话里）：

```bash
pip install mujoco numpy scipy imageio imageio-ffmpeg pillow pypinyin cmudict
cd sim
python live.py --open          # 打开 http://127.0.0.1:8000
```

不需要显示器或 OpenGL 窗口：画面由一个单独的进程离屏画好，用 MJPEG 推给浏览器。Linux 上默认用 EGL；如果报 EGL 的错，试 `MUJOCO_GL=glfw python live.py` 或 `MUJOCO_GL=osmesa python live.py`。macOS、Windows **我没试过**（我只在 Linux 上测了）。页面上能做的、该看到什么：

| 想验证什么 | 在观察台里怎么做 | 该看到什么 | 对应的验收项（`python accept.py --run standard --only X` 会跑出数字，X 是这一列里的项；`--run quick` 只会跑标了 quick 的那几项） |
|---|---|---|---|
| 自己找东西、夹起来、放进筐 | 点“开始收拾”（或打“收拾一下玩具”） | 日志里一行行：发现物体 → 前往 → 夹住 → 已放进收纳筐；右下角地图上黄块是它量到的物体、橙线是规划的路；左上角“送进筐里”从 0 涨到 5 | B1、A2（`standard`，约 12 分钟）；`python episode.py 4` 单跑一次 |
| 孩子冲过来，它会停 | 点“孩子冲过来” | 日志“有人在附近（… coming fast …），先停一下”；右边“安全层”变成“停住了”；孩子走后它接着干 | E3（安全层、碰到人 0 次） |
| 把人分成大人和小孩 | 点“大人走过来”“幼儿在筐边”“一家三口”，看右边“它看见的人” | 身高和“大人 / 小孩 / 拿不准”；真正在房间里的人在上面一行（“真”），看它看没看到 | E1、E2、E5（`python test_home.py people_static 150`） |
| 孩子不能让它做的事 | 点“孩子说：去充电（会被拒绝）” | 回“这个要大人来说哦”，不动 | F1、F4（权限表 76 种命令×角色） |
| 没喊它的话不该动 | 点“闲聊（没喊它，不该动）”（`/raw`，不自动加唤醒词） | 回“（没有回应：ignored: no wake word）”，不动 | F1（576 句闲聊 0 次误动） |
| 被推倒自己起来 | 点“推倒（左）”或“推倒（前）” | 日志出现 `[RIGHT]`，起来后“重新定位…”，回到 TASK 接着干 | C1、C2 |
| 没电了自己回去充电 | 点“电量调到 15%” | 它把手里的东西放进筐（“已放进收纳筐”），然后“电量低，停在两件事之间去充电”→ CHARGE →“去充电座”；充好再回来接着干（要几分钟，可以点 4×） | C3、C4 |
| 三维扫描家里 | 打“把家里扫描一遍” | 模式变 SCAN，它一个点一个点地走、转一圈，建三维地图（约两分钟） | D1、D2 |
| 安全层有没有用（对照） | 点“安全层 关”，再点“孩子冲过来” | 它不再因为孩子减速、停下，离孩子最近的距离明显变小 | E3 的“对照：关掉安全层”那一行 |
| 遥控 | 点“遥控 开”，点一下画面，W A S D（前后左右）、Q E（转） | 它跟着动；松手就停；人靠近安全层仍然管着 | C5 |
| 问问题、多轮对话 | 打“现在有谁”“你好”“你是谁”；打“去充电”它会问回来要不要，再打“好的” | 每句话的回答在“对话”里 | F1、F2、F3 |

**这个观察台里没有的**：① 声音（声源方向、声纹、电视的声音）——仿真里的声音是合成的，要用 `python test_sound.py ssl 100`、`python test_assoc.py assoc 200` 这些台架，数字在 `acceptance_sim.md` 的 G 组；② 打字绕过了语音识别（真机上是识别器写出字来再进同一条路），识别错了怎么办在 F1 里测；③ 登记人脸、记住孩子要有人站在它面前、有同意流程（“记住我，我叫爸爸”→“同意”），可以在观察台里先点“大人走过来”再打这些话试，**没有把它做成按钮**；④ 画面是仿真渲染的，不是机器人自己的相机看到的（机器人眼里的深度图在 `render_video.py clear` 的录像里）。

**速度**：默认 1×（仿真一秒等于真实一秒）；按钮“2× / 4×”要看你的电脑跟不跟得上，跟不上就按它能跑的速度跑。仿真本身在我这台没有显卡的 4 核机器上单核约 2 倍实时。

## 5. 别的验证办法

| 办法 | 做什么 | 适合 |
|---|---|---|
| 验收脚本 | `cd sim && python accept.py --list`（有哪些项、各自的标准）；`--run standard --only B1,E3`（只重跑这几项，在临时副本里，几分钟到几十分钟；`--run quick` 只跑标了 quick 的 14 项） | 要**数字和通过/没通过**，而不是“看着像”；见 [`acceptance_sim.md`](acceptance_sim.md) |
| 录像 | `MUJOCO_GL=egl python render_video.py 4 0.3 out.mp4`；`VIDEO_STEP=5 VIDEO_FPS=30` 更流畅；`render_video.py modes 3` 一次任务里接管、摔倒、充电连着来 | 发给别人看 |
| 遥控 TCP | `python live.py --tcp 9000`，另一个终端 `python teleop_client.py 127.0.0.1 9000`（键盘 w s a d q e，1 2 3 4 手臂，t 接管，r 交还，c 充电，p 状态）。我用一个 socket 客户端测过：`status` → `mode teleop` → `drive`，机器人真的动了 | 验证遥控协议和死人开关（`python test_modes.py server` 是它的自动测试） |
| 只看模型 | `python -m mujoco.viewer`，把 `model.build_xml(...)` 写出的 XML 拖进去 | 看底盘、手臂、相机的几何；这个窗口**没有在这个环境里试过** |

## 6. 一句话总结“功能是怎么集成的”

- **一条主线**：语音（或按钮）→ 请求模式 → 监督层 → 任务/技能 → 驱动层 → 世界；传感器读数一路往上。
- **两个“旁路”随时能插手**：监督层的抢占（摔倒、电量、操作员）和安全层（人）。它们不规划，只限制和切换，所以任何功能再多，**停得住**这件事不靠哪一个功能做对。
- **家里的知识**（三维地图、物件记录、人物画像）和语音是**接在监督层上的外挂**（`sup.home`、`sup.ppl`、`VoiceSystem`）：不装它们，捡东西这条主线照样跑（`episode.py` 就是这样跑的）。
- **仿真和真机的分界线是 `robot.py`**。这就是下一步要写的东西：真舵机驱动。
