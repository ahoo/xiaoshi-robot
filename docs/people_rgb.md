# 彩色图里的人体检测（RGB）：接口、仿真替身、和深度怎么合

**一句话**：纯深度检测分不开挨得很近的两个人（第十四轮写明的弱点）。这一轮加了“彩色图里的人体检测”这一路：每个人一个框，框里再去深度图上量位置和身高。**仿真里没法画出训练过的网络看到的人，所以检测器是替身，数字是我假定的，不是量出来的**；做出来、也测过的是我们自己写的那部分：框和深度怎么合、检测器漏了怎么办。真网络要真模型在真相机上量。**默认关**，要用设 `PEOPLE_RGB=sim`。

## 为什么要

深度图上的人是一块一块的“竖起来的东西”，分块靠的是它们在地面投影上彼此分开。孩子贴着大人（牵手、躲在大人前面）时两块连在一起：整块算“大人”，孩子的安全半径和说话权限都跟着大人走；一前一后站，孩子被挡住，一台相机本来就看不到。彩色图里的检测器不管有没有连在一起，每个人单独给一个框。

## 做了什么（`sim/rgbdet.py`、`sim/people.py`）

| 部分 | 是什么 |
|---|---|
| `BoxDetector` 接口 | `detect(cam) -> [(u0, v0, u1, v1, score), ...]`：相机彩色图上的像素框 |
| `SimBoxes`（**替身**） | 取分割图里每个人的真轮廓，给出一个带“小检测网络会犯的错”的框：目标在画面里小就找不到，被挡住的部分多就找不到，框会抖，偶尔在没人的地方给一个框。默认参数：清楚的人每帧找到 97%；画面里高 28 像素时找到一半；露出来不到 30% 时找到一半；框边抖 4%；每帧 2% 有一个假框。**都是假定的数字** |
| `OnnxBoxes`（真的） | 读一个 ONNX 人体检测模型（YOLOv5/v8 风格输出，COCO 80 类的只用“人”那一类），用 onnxruntime 在 `cam.rgb()` 上跑。**仓库里没有模型文件，这一段没跑过**：有了模型文件，只需要 `OnnxBoxes('xxx.onnx')` 传给 `PersonDetector(boxes=…)` |
| `box_detections`（融合） | 框 + 深度 → 给跟踪器的检测：把框按离机器人由近到远排；每个框取中间部分深度的中位数，再取和它差在 0.30 m 以内（沿地面量，不是沿光轴量：相机抬头看时，头比身子离光轴方向更远，不能按光轴深度截）的点作为这个人；被前面的人取走的点不算后面的人的，所以站在前面的人不会把后面的人盖住。身高、位置、肩宽都从这些点量 |
| 深度里没被框解释的部分 | 一块深度点没有任何框碰到：按纯深度的老办法量（一个人就是一个人，宽的“一群”判“不确定”）；被框取走一部分、剩下的：标成“不确定”（按小孩办）。所以**检测器漏掉一个人，结果最差也就是回到纯深度** |
| 开关 | 环境变量 `PEOPLE_RGB=sim`（用替身，默认参数），或 `PEOPLE_RGB='{"recall": 0.4, "h50_px": 110, "fp_per_frame": 0.25}'`（用替身，换参数）；代码里 `PersonDetector(…, boxes=make_boxes(robot, names, rng, rgb))` / `PeopleSystem(…, rgb=…)`。**不设就是纯深度检测：框和融合那一段完全不跑**（跟踪器的“滑行”这一轮改过一处，纯深度的结果因此和第十七轮比有细微变化，见下面） |

## 仿真里的结果

`sim/test_home.py pairs`（孩子和大人并排或一前一后，间隔 10/25/45/70 cm，各 32 次共 256 次，立杆相机，随机位置，看 2 秒）和 `people_static`（前臂相机，148 次）。验收项 E5 就是这些，标准写在 `sim/accept.py`。

| | 纯深度 | RGB 替身（假定质量） | RGB 替身（故意做得很差） |
|---|---|---|---|
| 一对人：两个人分成两条轨迹 | 224/256（87.5%） | **256/256（100%）** | 238/256（93%） |
| 一对人：孩子按小孩办（找到并判成孩子或拿不准，或和大人合成一块按小孩办） | 256/256 | 256/256 | 256/256 |
| 一对人：孩子被判成大人 | 0 | 0 | 0 |
| 站着的人：1–2.5 m 检出 | 96% | 96% | 96% |
| 站着的大人判成大人 | 46/46 | 46/46 | 43/46（其余拿不准） |
| 站着的孩子判成大人 | 0 | 0 | 0 |
| 空房间 48 帧的假目标 | 0 | 0 | 0 |

“故意做得很差”：清楚的人每帧也只找到 40%，画面里要高 110 像素以上才有一半（2 m 外的大人只有 80–100 像素），每帧 25% 有一个假框。合不上的那 18 次都是并排站、间隔 10 cm 的，检测器没找到，深度只看到一整块，按“不确定”处理（按小孩办）。

另外用别的种子各跑了三遍（一对人：种子 400/500/600；站着的人：种子 200/300/400，`PAIRS_SEED0`、`STATIC_SEED0`）：一对人纯深度分成两个人 222–224/256，替身 256/256，很差的替身 231–238/256，孩子判成大人全是 0；站着的人检出 97–100%、大人判成大人 98–100%（纯深度）、孩子判成大人 0。每帧 25% 有假框的那个很差的检测器，在种子 400 的空房间 48 帧里出现过 1 次假轨迹（假框连着两帧落在同一处），假定质量（每帧 2%）0 次。

**这些数字怎么读**：纯深度在这个（修好之后的）台架里已经不差，因为台架里人站在离家具 0.3 m 以上的空地上；RGB 把“两个人分开”从 87.5% 提高到 100%，主要是把合成一块的那 12.5% 分开了，**安全上的结论（孩子不会被当成大人）纯深度和 RGB 一样**。真正的家里，孩子贴着大人、被大人挡住、抱在怀里的时候，纯深度的分块更容易失败，这是 RGB 要解决的，**但要真模型在真相机上才量得出来**，仿真替身只是检验我们合的办法对不对。

## 这一轮顺手查出的台架毛病（会影响你看第十四轮的数字）

- 第十四轮的“一对人”台架（`pairs`）把机器人和人随机摆在房间里，**没避开家具**：机器人有时被摆在家具上或家具里，翻倒（我查的一条试验里倾角到了 1.8 rad，之后检出的位置乱飞）；“什么都没检出”的试验占 29%，同样的位置只放一个大人也只有 67% 检出（`pairs_control.py`），我当时把这归为“台架的性质”，**其实是台架的毛病**。现在机器人和两个人都离家具 ≥ 0.3 m，台架自己记机器人有没有翻倒（0 次）；改完以后纯深度一对人里什么都没检出的 0，只放一个大人 256/256 检出，孩子按小孩办 256/256。（顺手还改成先放人再放机器人，对结果没有影响。）第十四轮 `status.md` 里那张表是旧台架的结果，保留作历史。
- `people_static` 台架判“找到”是“0.6 m 内最近的一条轨迹”，家具（高柜）离人 0.3 m 时，被当成了他：一条试验里孩子根本不在相机视野里（分割图里他一个像素都没有），旁边 0.33 m 的高柜被判成“大人”，记成“孩子被判成大人”。找到的人位置误差中位数 8 cm、最大 17 cm，所以改成 0.30 m。
- 跟踪器 `PersonDetector` 的“滑行”有个老毛病：一条轨迹这一帧没有检测，位置按速度往前推，**推的时候用的是“距离上次看见的时间”，每帧都重新用一遍**，等于越推越多（第 n 帧推 n 倍）。查“做差的检测器”那组里的一次误判时看到：一条没被再看到的大人轨迹 10 帧里漂了 0.76 m，漂到了旁边孩子的位置上，被台架当成孩子的轨迹、判成“大人”。改成每帧只推这一帧的时间；测速度时也用最后一次真看见的位置。纯深度也走这一段，所以纯深度的结果理论上也会变，实测变得很少（见 `acceptance_sim.md`）。

## 实物上怎么接

1. 选一个人体检测模型，导出成 ONNX（输入 640×640 或更小，YOLOv5/v8 风格输出）。**许可证要自己看**：有的流行实现是 AGPL，要商用或闭源出货就不能用。**能不能在树莓派 5 的 CPU 上实时跑、要不要加速器，没测**。
2. `rgbdet.OnnxBoxes('模型.onnx')`，把 `conf`、`iou`、`size` 对着模型调；`PersonDetector(…, boxes=OnnxBoxes(…))`。
3. 实物验收表加了一行（第 71 项）：真模型在真相机上，孩子站大人旁边 10–45 cm 各 20 次，数“两个人分开找到”的次数和孩子判成大人的次数；再把 46、47、64 项用真模型重做一遍。
4. 在家里放的相机能看到的所有地方，量一次“没有人的时候假框的次数”（挂画、玩偶、镜子、电视里的人）：深度这一路会把没有人形深度的框扔掉，但电视屏幕是平的，扔不扔得掉要看。
