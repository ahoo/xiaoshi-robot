# 网页沙盘：不装任何东西，能玩，也能验证

**一句话**：一个网页（`web/playground/index.html`，也发布成了 Claude 里能直接打开的页面）。打开就能：对机器人说中文、让孩子冲过来、推倒它、调低电量、用键盘遥控、点房间让它去某处；页面一边玩一边判断“该看到的现象”出现没有；还能放**真实物理仿真录下来的数据**对照，并让沙盘的规则把真代码答过的 2600 多个情形再答一遍，看一不一样。

**它是什么，不是什么**（先说清楚，页面顶上也这么写）：沙盘里跑的是 JavaScript 写的**行为模型**，不是真的机器人代码，没有物理。规则是真代码的规则（逐行重写），而且**用数字比过**；机器人怎么走、怎么抓、怎么起身是简化的（计时和成功率）。真的物理仿真要在电脑上跑，见下面“想看真的在跑”。

## 怎么打开

| 办法 | 步骤 |
|---|---|
| Claude 里发布的页面 | 点会话里给的链接，什么都不用装 |
| 自己的电脑 | `cd web/playground && python -m http.server 8000`，浏览器打开 `http://127.0.0.1:8000/index.html`（直接双击 html 不行：页面要读同目录下的 `data/` 和 `tapes/`） |

## 页面上有什么

| 页 | 做什么 |
|---|---|
| 玩 | 对它说话（选谁在说：主人 / 大人（不认识）/ 孩子 / 看不清是谁；可以不喊“小拾小拾”试它会不会乱动）；让人走进来（孩子冲过来、大人走过来、幼儿在筐边、一家三口）；推倒、电量调到 15% 或 8%、关安全层、让它起不来；遥控（W A S D Q E）；点房间：站在这里 / 让它去这里 / 放一个人 / 把它搬到这里；日志；“它看到的人”和“真正在房间里的人”对照表 |
| 验证 | 15 条：做什么，该看到什么，做对了页面自己打勾；每条最后一行是**真实仿真里同一件事的验收结果**（引自 `results/acceptance_sim.json`，没通过的 E3 也照实显示） |
| 回放 | 7 段**真实物理仿真**的录像数据（收拾玩具、孩子冲过来、电量低、被推倒、一家人在家、扫描家里、孩子要它去充电），在同一个房间里放；每段旁边有“用沙盘重演同样的剧本”，可以把真实的和沙盘的并排看 |
| 对照 | 沙盘的规则和真代码的答案逐项比（见下），再比 5 个剧本的用时 |
| 说明 | 什么是真的、什么是模型、什么没做 |

## 什么是真的，什么是模型

| 部分 | 沙盘里 | 怎么保证 |
|---|---|---|
| 安全层（离人多远减速、停住；手臂在动时人在伸手范围内停下；孩子的距离更大；拿不准按孩子办；“请让一让”） | 真代码 `people.Guard` 逐行重写 | 2304 种情形（大人/小孩/拿不准 × 4 个方向 × 12 个距离 × 4 种走近速度 × 2 种机器人速度 × 手臂忙不忙）和真代码的答案**全部一样**（停不停、减到多少） |
| 中文：唤醒词、停止词、按拼音近似匹配听意图、谁能让它做什么、拿不准先问、答“对”才动、缺东西追问 | 真代码 `voice.py` 的规则和同一个匹配算法，拼音表从 `pypinyin` 导出 | 336 句 × 4 种说话人：沙盘做了的 327 句，意图、动作、说出口的话**逐字一样**；10 段多轮对话（问了再答对 / 不是 / 隔太久 / 孩子答对 / 不带唤醒词的停下……）**全部一样** |
| 电池（读数有偏差、20% 去充、10% 马上去、充电曲线） | 真代码 `power.py` 的公式和常数 | 6 个起点的充电时间、电压和真代码相同 |
| 模式（收玩具、导航、扫描、遥控、充电、起身、待命、故障）谁能打断谁，打断后怎么接着做 | 真代码 `modes.py` 的逻辑，用同样结构的生成器重写 | “对照”页第 4 部分：5 个剧本里真实仿真和沙盘的**模式变化先后一样**（如 IDLE→TASK→RIGHT→TASK、IDLE→TASK→CHARGE→TASK→CHARGE；真实录像在充电中就截止了，沙盘多跑了 30 秒，所以多一个最后的 →IDLE）；用时差多少照实列出 |
| 人的脚本（进门、走、追、站、坐、出门）和大人/孩子的分类阈值（1.30 / 1.50 m、肩宽 0.37 m） | 真代码 `people.Script`、`classify` 重写 | 同一套步骤 |
| 机器人怎么走、怎么抓、怎么起身、功率 | **简化**：A* 路线 + 匀速；抓取是 9.6 秒计时 + `results/grasp_bench.json` 的实测成功率，最多试 4 次；起身是录像里的计时；功率是录像里各状态的平均值 | 只能说数量级接近，差多少见“对照”第 4 部分 |
| 它看到什么 | **简化**：相机 ±35°、5 米内、没有噪声；雷达看到在动的东西记成“拿不准” | 真实的深度图检测和分类由验收 E1、E2、E5 测 |
| 物理（摩擦、夹得住夹不住、摔倒的力学）、真实相机和雷达的数据 | **没有** | 看“回放”，或在电脑上跑真仿真 |
| 英文、中英夹杂、记住人/忘掉人、给东西起名、声音从哪来、声纹、画像 | **没有**（说了会告诉你没做） | 真系统有，验收 E4、F2、G1–G4、H1 |

### 对照出来的数字（2026-11-25，代码版本见页面“说明”）

- 说的话：336 句里 327 句一样、0 句不一样、9 句沙盘没做（英文、记人/忘人的流程）；多轮对话 10/10 一样。
- 安全层：2304/2304 一样。
- 电池：6 个起点的充电时间完全相同。
- **同一个剧本，真实仿真 vs 沙盘**（种子 4 号房间；差得多的地方就是沙盘不可信的地方）：

| 剧本 | 量 | 真实仿真 | 沙盘 |
|---|---|---|---|
| 孩子冲过来 | 安全层停住次数 / 第一次停住 / 停了多久 / 碰到人 | 1 / 41.3 s / 2.2 s / 0 | 1 / 41.1 s / 2.0 s / 0 |
| 被推倒 | 摔倒到回到收玩具 | 28.7 s | 34.0 s |
| 电量低（15%） | 去充电的时间点 / 充电用时 | 79 s / 96 分 | 76 s / 94 分 |
| 整套收玩具 | 第 5 件放进筐 / 任务结束（放完后真系统还满屋巡一圈再回起点） | 252 s / 466 s | 195 s / 282 s |
| 扫描家里 | 用时 / 停靠点 | 110 s / 4 个 | 81 s / 3 个 |

  规则相关的量（安全层停几次、什么时候停、碰没碰到）几乎一样；**用时相关的量沙盘偏快 20%–40%**（走得直、没有真系统那样的重新规划和慢慢对位），沙盘里的“要多久”别当真。

### 对照顺手查出的一处真代码的毛病

拼音近似匹配会把“巡视一下”听成“记一下”：真代码里 `enrol`（记住一个人）的短语“记一下”和“巡视一下”的后三个音（shi yi xia / ji yi xia）差得不够多，得分 0.84，压过了 `scan_home` 的“巡视”（0.79）。结果主人说“巡视一下”，它会开始问“请问他叫什么名字？”（记人的流程）而不是去扫描。登记还要名字和大人同意，不会自己存东西，孩子也不能触发，所以不危险，只是听错了。**没改**（会动到 F1–F3 验收，要重跑）；想改的办法是让记人/忘人/静音这几个敏感的意图用精确匹配。沙盘把这一句列在“没做”里。

## 数据和代码从哪来

| 文件 | 做什么 |
|---|---|
| `sim/export_playground.py` | 从仓库导出 `web/playground/data/model.json`：常量、房间、12 个布局、词表、拼音表、抓取成功率、验收结果，以及**真代码对 336 句 × 4 种说话人、10 段对话、2304 种安全层情形、充电曲线的答案**（“golden”） |
| `sim/record_tapes.py` | 在真实物理仿真里按固定剧本跑，每秒记 5 帧（机器人、东西、人的真实位置，模式，电量，安全层，它的跟踪），存成 `web/playground/tapes/*.json`；同样的种子给同样的结果；`python record_tapes.py --list` |
| `web/playground/xs_logic.js` | 电池、安全层、中文对话（真代码规则的 JavaScript 版） |
| `web/playground/xs_world.js` | 房间、人、它看到什么、模式管理（生成器）、路线、抓取计时 |
| `web/playground/ui.js`、`playground.src.html` | 页面 |
| `web/playground/build.py` | 拼成 `index.html`（完整页面）和 `dist/artifact.html`（去掉外层文档标签，发布用） |
| `web/playground/test_core.mjs` | `node web/playground/test_core.mjs`：在 node 里做“对照”页上那些比较，有不一样的会列出来 |
| `web/playground/test_world.mjs` | `node web/playground/test_world.mjs [tidy\|kid\|lowbat\|fall\|scan\|voice\|teleop]`：不开页面把剧本跑一遍并检查 |

重新生成：

```bash
cd sim
python export_playground.py            # 15 秒
python record_tapes.py                 # 全部 7 段，4 个进程并行，约 10 分钟（真物理，约 1× 实时）
cd ../web/playground && python build.py
```

## 想看真的在跑

沙盘之外的两条路（都是真代码、真物理，有 3D 画面）：

1. **自己的电脑**：`pip install mujoco numpy scipy imageio imageio-ffmpeg pillow pypinyin cmudict`，然后 `cd sim && python live.py --open`，见 [`architecture.md`](architecture.md)。
2. **GitHub Codespaces**（浏览器里的开发环境，不装东西）：仓库里放了 `.devcontainer/devcontainer.json`，开 Codespace 后在终端里 `cd sim && python live.py`，右下角会弹出转发的 8000 端口，点开。**这一条我没有在 Codespaces 里试过**：只在这台机器上确认了命令本身能跑、装包的那一行是 README 里原来就有的；Codespaces 里图形库（EGL）装得上装不上、软件渲染够不够快，没验证。

## 已知的限制

- 沙盘的“送进筐里”用时偏快（见上表）；最后那圈确认地上没东西了的巡视比真系统短。
- 沙盘里去“沙发那边”时，停靠点比真代码宽松（真代码只试沙发四边的中点，这个房间里四个点都被别的家具挡住，会说去不了；沙盘找 0.4–0.75 m 内任何空地）。
- 人只有 5 个固定的人（大人 2、孩子 3），行为是预设的脚本；点画面放的人站着不动、看着机器人。
- 验证页的 15 条是“做对了就打勾”，不是验收：验收是真实仿真里几十到几千次的统计，那个看 [`validation.md`](validation.md) 和 `results/acceptance_sim.json`。
